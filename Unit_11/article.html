No-Code 實作

手上的 Figma 檔案不會自己變成網站。這堂課做兩件銜接的事：先把設計交接好——讓工程師看得懂、接得住；再用 AI 工具把同一份設計直接生成一個能在瀏覽器打開的網頁。兩件事共用同一個邏輯：把設計脈絡講清楚，對方（不管是人還是 AI）才能做出你要的東西。Unit 12 專題發表時，這個網頁會是你的作品之一。

閱讀時間約 16 分鐘 搭配 Unit 11 投影片 含練習、作業與 AI 提示詞

01

開發者不是最後一站的收件人

Figma 官方對交接的說法很直接：把開發者當協作夥伴，不是流程最後才收到檔案的人。Dropbox、Expedia、Cash App 等團隊的做法顯示，及早分享檔案、保持設計過程透明、讓開發者看得到迭代——不是只看最終畫面——是建立設計師與工程師互信的關鍵。

做法結果
做完整份設計才丟連結工程師第一次看到就要馬上實作，問題到這時候才浮現
設計進行中就邀請開發者加入能持續提問、給回饋，交接時的意外狀況變少

02

交接前要準備的事

丟連結之前，這些是 Figma 官方列出的準備工作：

  • 用 Emoji 標示頁面狀態（例如 🏗️ 施工中、💭 待討論、🚢 可上線），讓人一眼看出哪些設計還在改、哪些已經定案。
  • 幫關鍵 Frame 設定自訂縮圖，在檔案瀏覽時提供視覺線索。
  • 把最終設計做成 Component Instance，放在乾淨、整理過的頁面，跟散亂的工作區分開。
  • Component 完整記錄：名稱、說明、使用方式、Variant 都要寫清楚。
  • Style 與 Variable 命名要跟程式碼庫慣例一致。
  • 主元件旁邊附說明 Frame，讓開發者可以直接參考。
  • Component 的說明欄位加無障礙注意事項與相關連結。
  • 確保開發者能存取設計系統資料庫，裡面包含所有主元件。

03

Dev Mode 是什麼

Dev Mode 是「一個以開發者為中心的介面，用來檢視與瀏覽設計」，提供進階的檢視工具、程式碼產生、版本比較與整合功能，簡化交接流程。

開啟方式：打開一份 Figma Design 檔案，點工具列上的 Dev Mode 切換鈕，或按快捷鍵 Shift + D。同樣的快捷鍵可以切回 Design 模式。

Ready for dev 狀態：標示某個 Component、Frame 或 Section 已經準備好交給開發者實作。設計師標記後，會出現在 Dev Mode 的導覽面板裡。Organization／Enterprise 方案還多一個「Completed」狀態可以追蹤進度。

04

Dev Mode 提供的資訊

項目內容
程式碼片段多種語言的程式碼片段，可透過外掛（如 Tailwind、React）自訂輸出格式
圖層屬性版面、間距、顏色、互動設定
測量與標註間距與尺寸的視覺化標示
可下載素材自動偵測的圖示、圖片、影片
元件中繼資料Variant、屬性，可以直接互動測試
設計變更版本歷史比對
外部資源連結可連到 GitHub、Jira、Storybook、VS Code

05

溝通做法：早期協作與有脈絡的說明

  • 邀請開發者以 Viewer 身分加入檔案。免費、不需要付費授權，讓他們可以檢視、匯出素材、看程式碼、留言。
  • 提供有脈絡的說明文件，而不是傳統的紅線標註稿。分享問題定義、研究過程、迭代決策的敘事脈絡；用 Code Panel 顯示 CSS、iOS、Android 的程式碼片段搭配元件細節。
  • 鼓勵早期協作。讓開發者在設計還在進行時就加入檔案，能持續提問、給回饋，而不是等做完才發現問題，減少交接時的意外狀況。
工程師要知道的是「為什麼這樣設計」，不是只知道「這裡是 16px」。紅線標註稿告訴他數字，敘事脈絡告訴他理由——理由才是他判斷「這個能不能改」的依據。

06

Claude Code 是什麼

Claude Code 是「一個活在終端機裡的 agentic 編碼工具，能理解你的程式碼庫，透過執行例行任務、解釋複雜程式碼、處理 git 工作流程，幫你更快寫程式——全部用自然語言下指令」。

它不是一個「生成程式碼的聊天介面」，而是一個會規劃工作、讀你的程式碼庫、跨多個目錄編輯檔案、跑測試、建立 Pull Request 的 Agent。安裝完成後，在任何專案資料夾執行 claude 就能開始互動式工作階段。

CLI 版本是功能最完整的介面——新功能最先出現在這裡。VS Code 擴充套件、JetBrains 外掛、桌面應用程式與網頁介面都共用同一套底層引擎，CLI 裡設定的東西在其他介面也通用。

07

Figma MCP：讓 Claude Code 讀懂設計

Figma MCP Server 讓 Claude Code「讀取結構化的設計脈絡——包含 Component、Variable、版面資料、FigJam 內容——並且能從選取的 Frame 產生程式碼，透過 Code Connect 讓產生的程式碼跟真正的元件保持一致」。連上之後，Claude Code 能讀到 Figma 檔案裡實際的顏色、間距、Component Variant，不需要人工把設計規格再轉譯一次成文字。

08

設定步驟

Remote 版本是官方建議大多數人使用的方式：

  1. 在終端機執行 claude plugin install figma@claude-plugins-official。
  2. 按 Enter，重新啟動 Claude Code。
  3. 輸入 /plugin，切到 Installed 分頁。
  4. 選取 figma 伺服器，按 Enter 進行授權登入。
  5. 在跳出的外部授權頁面點「Allow access」。
  6. 回到終端機再執行一次 /plugin，確認 figma 伺服器顯示為已連線。
Desktop 版本（Enterprise 專用）可以透過 Figma App 的 Dev Mode 啟用桌面版 MCP Server，再用 claude mcp add 指令設定——大多數課堂情境用不到，知道有這個選項即可。

09

兩種工作方式

方式做法
選取式（Selection-based）在 Figma 裡選取一個 Frame 或 Component，跟 Claude 說「幫這張卡片加一個按鈕」
連結式（Link-based）直接貼 Figma 連結，跟 Claude 說「把這個註冊卡片設計轉成程式碼：[figma 連結]」

兩種方式都需要先確定「要對哪個範圍講話」——選取式限定在你選的那個 Frame；連結式讓 Claude 自己去讀連結指到的節點。圖層命名清楚一點（例如「CTA 按鈕」而不是「Frame 47」），有助 AI 辨識結構。

10

Gemini CLI

Gemini CLI 是 Google 的開源 AI 終端機助手，把 Gemini 模型整合進命令列工作流程，讓開發者能在終端機裡自動化除錯、重構程式碼、產生測試、寫文件。以互動式的 REPL（Read-Eval-Print Loop）環境運作，內建 Google 搜尋、檔案操作、Shell 指令、網頁擷取等工具，並支援 MCP，可以用類似的方式接上其他資料來源（包含 Figma）。

清華大學課程大綱把 Claude Code 與 Gemini CLI 並列為「介紹用的 AI 網頁生成工具」——兩者的核心能力類似：讀懂脈絡、用自然語言下指令、直接修改檔案。上課示範用哪一個，看現場環境跟帳號能不能用決定，操作邏輯是共通的。

個人 Google 帳號的免費額度是每分鐘 60 次、每天 1,000 次請求——這個數字依 Google 官方公告為準，可能會調整，上課前建議先查最新額度再決定要不要用它做課堂練習。

11

溝通模擬：跟 AI 練習解釋設計決策

清華大學課程大綱的做法：學生可以請 Gemini 扮演「挑剔的工程師」或「預算有限的客戶」，練習如何解釋自己的設計決策並應對質疑。

這個練習不是要說服 AI，是練習把「為什麼這樣設計」講清楚。工程師會質疑技術可行性與工時，客戶會質疑成本與必要性——兩種角色問的問題不一樣，你回答的角度也要不一樣。Unit 12 專題發表會被真人問到類似的問題，這裡先練一次。

12

課堂練習與回家作業

課堂練習用 90 分鐘，四個階段接著做：交接準備 → 工具設定 → 生成網頁 → 溝通模擬。完整步驟、時間分配與交件標準在練習頁。

回家作業把課堂練的工具實際用在自己專題的一個核心畫面上，跑出一個真的能打開的網頁，細節在練習頁的回家作業。

13

AI 協作提示詞

這三段提示詞用在課堂練習與回家作業。前兩段是操作 Claude Code／Gemini CLI 時直接可以用的指令句型；第三段是溝通模擬的角色扮演腳本。

① 選取式：針對選取的 Frame 下指令

我已經在 Figma 裡選取了一個 Frame，名稱是「[貼上你的 Frame 名稱]」。

請根據這個 Frame 目前的版面、文字內容與配色，生成一個單一 HTML 檔案（內嵌 CSS，不需要外部框架），要求：

1. 響應式（RWD）：寬螢幕維持目前的版面比例，窄於 700px 時改成適合手機操作的排版——多欄內容通常改直向堆疊，導覽列這類元素可以改成收合選單，原則是內容不能被截斷、也不能出現需要左右捲動的溢出。
2. 文字內容、標題、按鈕文案都要跟 Figma 裡看到的一致，不要自己編新的文案。
3. 配色沿用 Figma 裡的顏色，不要換成別的配色。

完成後告訴我你依據了哪些圖層或 Component 做出對應的區塊。

② 連結式：貼連結直接轉換

把這個 Figma 設計轉成程式碼：[貼上你的 Figma 檔案或 Frame 連結]

要求：

1. 輸出一個單一 HTML 檔案（內嵌 CSS），檔名為 index.html。
2. 響應式（RWD），手機寬度時排版要適合手機操作（常見做法是多欄改直向堆疊、導覽列改收合選單），內容不能被截斷或出現左右溢出。
3. 版面結構、文字、配色要跟設計稿一致。

如果連結裡有多個 Frame，先列出你看到的所有 Frame 名稱，讓我確認要轉換哪一個，再開始生成。

③ 溝通模擬：扮演挑剔的工程師／預算有限的客戶

請你扮演一位「挑剔的工程師」（或：「預算有限的客戶」，兩種角色我會分開各練一次），我會跟你說明我的設計決策，你要用這個角色的立場質疑我。

我的設計背景：

[貼上你的專題一句話說明：使用者是誰、要解決什麼問題]

我要說明的設計決策：

[貼上你想解釋的一個具體決策，例如「為什麼登入頁用這個欄位順序」]

請你：

1. 用這個角色會問的方式提出至少 3 個尖銳的問題（工程師關心技術可行性、維護成本、邊界情況；客戶關心費用、時程、對業務的必要性）。
2. 我回答之後，指出我的回答有沒有真的回應到問題，還是在迴避。
3. 不要幫我想答案，只負責質疑與判斷我的回答夠不夠有說服力。
