課堂練習 · 90 分鐘

從交接文件到一個能打開的網頁

四個階段接著做，中間不停。做不完的部分列進回家作業。

Exercise 01

交接準備：標記 Ready for dev

15 分鐘個人Figma

打開你自己專題目前的 Figma 檔案，練習把它整理成「工程師接得住」的狀態。

步驟

  1. 檢查頁面命名，幫還在改的頁面加上 🏗️，待討論的加 💭，已經定案的加 🚢。
  2. 挑 3 個你這學期做過的 Component（例如按鈕、卡片），確認名稱清楚、有補上使用說明。沒有說明的現在補一句。
  3. 按 Shift + D 切到 Dev Mode，找到這 3 個 Component，標記為 Ready for dev。
  4. 在 Dev Mode 裡點開其中一個，看一下 Code Panel 顯示的程式碼片段長什麼樣子——不用看懂，只要知道這個功能在哪裡、開發者會看到什麼。
交件：3 個 Component 都標記 Ready for dev，且都有名稱與使用說明。

Exercise 02

設定 Claude Code／Gemini CLI + Figma MCP

30 分鐘個人終端機 + Figma

把 AI 工具接上你的 Figma 帳號。以 Claude Code 為例（Gemini CLI 的 MCP 設定邏輯類似，跟著現場示範做）：

步驟

  1. 打開終端機，執行 claude plugin install figma@claude-plugins-official。
  2. 按 Enter，重新啟動 Claude Code。
  3. 輸入 /plugin，切到 Installed 分頁，選取 figma 伺服器，按 Enter。
  4. 瀏覽器會跳出授權頁面，點 Allow access。
  5. 回到終端機，再打一次 /plugin，確認 figma 伺服器顯示為已連線（connected）。
  6. 連線成功後，貼上講義第 9 節的範例設計稿連結（開啟範例設計稿），跟 Claude Code 說「幫我看一下這個連結指到的 Frame，回報它的名稱跟裡面有哪些主要區塊」，確認它真的讀得到內容。
常卡住：/plugin 裡沒看到 figma 或顯示未連線，通常是「退出再重新啟動 Claude Code」這一步被跳過，或授權頁面沒有點完 Allow access。整個流程重跑一次，不要在中間步驟卡住時硬按下一步。
交件：Figma MCP 顯示已連線，且 Claude Code 有正確回報範例設計稿的 Frame 名稱與主要區塊。

Exercise 03

把一個畫面轉成真的網頁

30 分鐘個人終端機 + Figma

先在自己的電腦上開一個空白資料夾（例如桌面新增 unit11-demo），在終端機 cd進去之後再執行 claude——生成的檔案會放在這個資料夾裡，之後好找。

主要方式：連結式

  1. 開啟範例設計稿：學習角線上課程報名頁（也可以換成你自己 Unit 03 做的卡片畫面）。
  2. 在 Figma 裡右鍵點這個 Frame → Copy link to selection，複製連結。
  3. 回到終端機，跟 Claude Code 說：「把這個 Figma 設計轉成程式碼：[貼上連結]」（完整指令句型見講義第 13 節提示詞②）。
  4. 如果它問你要轉哪個 Frame，明確回答，不要讓它自己猜。
  5. 等它跑完，打開產生的 HTML 檔案，跟原本的 Figma 設計對照，檢查文字、配色是否一致。

時間夠的話，再試試看：選取式

  1. 在 Figma 裡直接選取同一個 Frame（不用複製連結）。
  2. 跟 Claude Code 說：「幫我把選取的這個 Frame 轉成一個響應式的 HTML 網頁」（完整指令句型見講義第 13 節提示詞①）。
  3. 比較這次跟連結式做出來的結果，是不是需要重新確認一次「選到的範圍對不對」。

不管哪種方式，都要做的事

  • 把瀏覽器縮小到手機寬度，確認排版有跟著調整成適合手機操作（多欄改直向堆疊、導覽收合皆可），內容沒有被截斷或左右溢出。
  • 對照 Figma 設計稿，文字內容跟顏色有沒有跑掉。
常卡住：生出來的網頁跟設計對不上，通常是選取的 Frame 範圍不對，或圖層命名太亂讓 AI 誤判結構——圖層命名清楚一點（例如「CTA 按鈕」而不是「Frame 47」），有助 AI 辨識結構。
交件：一個能在瀏覽器打開的 HTML 檔案，縮小視窗寬度時排版會跟著調整、沒有內容被截斷或溢出，文字與配色跟原設計一致。

Exercise 04

溝通模擬：跟 AI 練習解釋設計決策

15 分鐘個人AI 對話

挑一個你這學期做過、自己覺得有把握解釋的設計決策（例如「為什麼登入頁欄位排這個順序」）。

步驟

  1. 打開任一 AI 對話工具，貼上講義第 13 節提示詞③，先選「挑剔的工程師」這個角色。
  2. 照提示詞的格式填入你的專題背景與要解釋的決策。
  3. AI 提出質疑後，實際打字回答——不要只在腦中想，要寫下來。
  4. 看 AI 怎麼評你的回答：有沒有真的回應到問題，還是在迴避。
  5. 時間夠的話，換成「預算有限的客戶」角色再做一次，比較兩種角色問的問題有什麼不同。
交件：至少完成一輪「工程師」角色的問答，記下 AI 指出你哪一句回答在迴避問題。
回家作業

把專題畫面轉成網頁

預估 2.5 小時。把課堂練的工具實際用在自己的專題上，交出一個真的能打開的網頁。

Homework

一個真的能打開的專題網頁 + 溝通模擬紀錄

約 2.5 小時個人終端機 + Figma
  1. 挑自己專題的一個核心畫面（例如首頁或最重要的操作流程頁），先照 Exercise 01 的做法整理交接狀態：命名清楚、Component 有說明、標記 Ready for dev。
  2. 用 Claude Code 或 Gemini CLI 把這個畫面轉成網頁。選取式或連結式都可以，生成後自己檢查響應式效果、文字與配色是否跟設計一致。
  3. 至少修正一輪。對照原設計，找出生成結果哪裡不對，再跟 AI 說明要怎麼調整，記錄下你下了什麼指令、改了什麼。
  4. 完成一輪完整的溝通模擬。「挑剔的工程師」角色必做，記錄 AI 問了哪些問題、你怎麼回答。時間夠的話再做「預算有限的客戶」角色（加分項）。

交件前自己跑一次這個檢查

  • 生出來的 HTML 檔案，直接用瀏覽器打開會不會正確顯示？
  • 縮小視窗寬度到手機尺寸，版面會不會跟著改變？
  • 兩個角色的溝通模擬，有沒有記下具體的問答內容，不是只寫「有做」？

AI 使用界線

可以不可以
生成網頁讓 AI 依照 Figma 設計生成程式碼，並指出哪裡跟設計不符讓 AI 自己決定要不要改動你的設計內容或版面結構
溝通模擬讓 AI 扮演角色質疑你，練習組織回答讓 AI 幫你想好答案直接照唸，沒有自己組織過

界線的邏輯：AI 可以幫你把設計轉成程式碼、幫你練習被質疑，不能幫你決定設計本身或幫你想好每一句答案。三段提示詞在講義第 13 節。

交件方式：HTML 檔案（或部署後的連結）+ 一份溝通模擬紀錄（文字檔或截圖皆可），下次上課抽點分享。

Submission

HTML 檔案 + 溝通紀錄下次上課抽點分享

要交的東西

  • 1 個交接整理過的核心畫面（命名清楚、Component 有說明、標記 Ready for dev），附 Figma 連結或 Dev Mode 截圖供檢查

  • 「挑剔的工程師」角色的溝通模擬紀錄（必做）；「預算有限的客戶」角色為加分項
