產品設計基本元素

Unit 03 學會了怎麼在 Figma 裡操作，這堂課換內容：顏色、文字、Icon、按鈕這四樣東西，要怎麼決定規則，而不是每次畫畫面都重新選一次。色彩角色系統讓「這個顏色用在哪裡」有明確答案；Type Scale 讓字級不用每頁重新猜；Icon 有尺寸與對齊的準則；按鈕要設計的不只一個樣子，是五種狀態。這四件事定好之後，會變成整個專題重複使用的規範，Unit 06 開始畫真的介面時直接套用。

01

色彩角色：每個顏色一個工作

Material Design 3 用色彩角色（Color Role）取代「固定色票」——每個角色有明確的用途，不是單純的一組顏色。角色名稱前綴 On 的顏色，代表疊在對應角色顏色「上面」的內容色（文字、圖示），這個配對關係本身就是為了確保對比度足夠、內容看得清楚。

角色用途
Primary / On Primary主品牌色與其對比色，用在關鍵動作與高強調元素
Primary ContainerPrimary 的淺色（深色模式下較暗）版本，用於強調程度較低的元件，例如填色按鈕、選取狀態
Secondary / TertiarySecondary 用在次要動作、Chip 等較不顯眼的元件；Tertiary 提供第三種強調色，做視覺平衡
Surface / On SurfaceSurface 是卡片、Sheet、選單等元件的背景色；On Surface 是疊在上面的文字與圖示
Surface Variant / On Surface VariantSurface 的替代版本，用於需要輕微區隔的區塊；On Surface Variant 是強調程度較低的文字
Outline用在邊框與分隔線
Error / On Error錯誤狀態的顏色與其對比色

02

怎麼選色彩方案

一個色彩方案（color scheme）描述一個產品在亮／暗兩種主題下的所有顏色、色彩角色與彼此的關係。Material 3 的作法是從單一來源色（source color／seed color，通常是品牌色），用演算法自動生成一整套跟色彩角色一一對應的完整色階（Primary、Secondary、Tertiary、Neutral、Error 各自的色階），不用逐一手動挑幾十種顏色深淺。

  1. 挑來源色。建議「不要太飽和，也不要太灰」——中等飽和度的顏色效果最好。
  2. 產生色階。演算法生成 Primary／Secondary／Tertiary／Neutral／Error 各自的完整色階。
  3. 套進角色。每個角色從對應色階取一個色階值，亮／暗兩種主題各一套。

來源色可以直接用官方基準色，也可以自訂品牌色，或依使用者產生的內容／情境動態決定。

03

WCAG 對比度門檻

色彩角色選好之後，還要過對比度這道檢查。這不是美感問題——研究顯示視力約 20/40（常見的視力障礙門檻）的使用者，大約需要這個對比度才能舒適閱讀文字。

等級文字大小最低對比度
WCAG AA一般文字（18pt 以下，或 14pt 以下的粗體）4.5:1
WCAG AA大字級文字（18pt 以上，或 14pt 以上的粗體）3:1
WCAG AAA一般文字7:1
WCAG AAA大字級文字4.5:1
例外：純裝飾用、不會顯示給任何人看的文字、圖片裡含大量其他視覺內容的文字，以及品牌 Logo／商標文字，不受這個門檻限制。介面上其他所有文字都要過 AA 等級的門檻。

04

Type Scale：五組角色

Type Scale（字級量表）是一組可以在整個產品裡重複使用的字體樣式，提供足夠的風格彈性去對應不同用途，同時維持一致、容易辨識的風格。Material Design 3 把 Type Scale 組織成 5 組角色，每組再分 Large／Medium／Small 三個級別。

角色組用途
Display畫面上最大的文字，保留給簡短、重要的文字或數字
Headline中等大小，用在區塊標題、次標題
Title比 Headline 小，常用在 Card、對話框裡的內容標題
Body標準內文字級，用在較長的段落與主要內容
Label最小的角色，用在圖片標註，以及按鈕、分頁標籤這類重要介面元素

05

每個字級 Token 記錄的四件事

每一個 Type Scale 的 Token（例如 Body Large、Label Small）都同時記錄四項屬性：

  • Font size（字級）：文字的視覺大小。
  • Line height（行高）：確保可讀性的垂直間距。
  • Font weight（字重）：文字的粗細與強調程度。
  • Letter spacing（字距／Tracking）：調整字元密度的水平間距。
一套 Type Scale 訂好之後，設計時只要從 15 個 Token 裡挑對應角色使用，不用每個畫面各自決定字級——這是維持整個產品文字風格一致的關鍵做法。

06

Icon 設計原則

Icon 的尺寸有限，每一個都必須嚴格遵守設計準則，同時仍要表達出這個概念最核心的特徵。

  • 簡化，讓概念容易理解，同時提高辨識度。
  • 避免複雜的設計。細節在小尺寸下會糊成一團。
  • 用幾何、粗體的形狀，而不是細緻、寫實的描繪。

Icon 的設計目標是簡單、現代、友善，有時候可以帶一點趣味，但前提是不能犧牲辨識度。

07

Icon 尺寸與跟文字搭配

標準 Icon 尺寸是 24dp × 24dp。額外支援 20dp、40dp、48dp 三種尺寸：20dp 主要用在桌面、資訊密度高的版面與小型視覺元素，40dp、48dp 適合搭配 Display／Headline 這類大字級文字，以及較大的螢幕尺寸。

跟文字對齊時，官方建議把 Icon 的基準線（baseline）往下移動大約文字字級的 11.5%，這樣 Icon 跟文字才會在視覺上對齊一致。

無障礙注意事項：加上 ARIA 標籤（或對應平台的替代文字）；區分「裝飾用」與「傳達資訊用」的 Icon，只有傳達資訊的才需要文字替代描述；同樣要考慮對比度與最小可點擊區域。

08

按鈕五個狀態

按鈕不是畫一次就好，至少要設計五個核心狀態：

狀態代表意思視覺處理
Enabled（預設）按鈕已準備好被點擊高對比、清楚的標籤文字
Hover游標移到按鈕上，確認可以點擊顏色些微加深，或加陰影浮起效果
Pressed / Active使用者正在點擊、按住的瞬間顏色些微變化，常搭配輕微縮小（約 0.98 倍）模擬按壓回饋
Focus使用者用鍵盤（Tab）導覽到這個按鈕清楚可見的外框，不能只靠顏色變化——這是無障礙的硬性要求
Disabled這個動作目前不可用降低飽和度與對比，但文字仍要維持可讀

按下（Pressed）狀態的視覺回饋要在 100–150 毫秒內出現，避免使用者因為看不到反應而重複點擊。複雜流程還會用到 Loading（轉圈或進度條）與 Selected／Toggled（切換型按鈕維持的持續樣式，跟按下瞬間的 Pressed 不同）。

09

按鈕標籤文字的寫法

  • 標籤用動詞。具體的動作型標籤能讓使用者一眼看出這是可以互動的按鈕，也知道點下去會發生什麼事。
  • 用標題大小寫（Title Case）。除了四個字母以下的冠詞、對等連接詞、介系詞之外，每個字首都大寫。
  • 標籤要簡短。過長的文字會讓介面顯得擁擠，在較小的螢幕上還可能被截斷。
  • 邊框與背景只在必要時才加。系統按鈕預設沒有邊框或背景；某些內容區塊裡需要邊框或背景才能表達「這是可以互動的」時才加上去。

10

在 Figma 裡怎麼組織

  1. 用 Component Variants 把同一顆按鈕的所有狀態收進同一個 Component Set，每個狀態是一個 Variant，屬性命名 State。
  2. 在 Prototype 分頁用 Trigger（例如 While hovering、Mouse down）把各個 Variant 連接起來，模擬狀態切換。
  3. 轉場動畫建議用 Smart Animate，時長約 150 毫秒，讓狀態切換感覺跟得上使用者的操作節奏。

11

課堂練習與回家作業

課堂練習用 80 分鐘，把今天四個規範疊在同一份風格小卡上做出來：色彩角色卡 → Type Scale 應用 → Icon 對齊 → 按鈕 5 狀態。完整步驟、時間分配與交件標準在練習頁。

回家作業把課堂的風格小卡擴充成套用在真實畫面上的一頁風格指南，細節在練習頁的回家作業。
