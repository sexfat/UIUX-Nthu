## 單元目標

- 理解一份設計規範文件的結構：規則、原因、Do/Don't 範例，以及可勾選的檢核表。
- 能拆解一份現成的規範文件（本班 APP UI 設計規範），看懂它怎麼把平台差異寫成規則。
- 能用 AI 協助把自己專題的判斷，整理成別人看得懂、能照著做的規範文件。
- 知道 AI 幫不了的部分：數字要回頭核對來源，規則要不要收進文件是設計判斷。

## 課程介紹

這個單元原本是「APP UI 設計規範」，內容沿用不變（iOS／Android 的畫布、單位、安全區域、導覽、表單、無障礙判斷）；但整堂課的主軸調整成 Design System：把這份 APP 規範當成一個**範例**——「一份好的規範文件長這樣」——再帶到怎麼用 AI 把自己專題的判斷寫成一份規範文件、寫成一份檢核表。

⚠️ **First draft 備註：** §1–§11（原 APP UI 規範內容）保留原有的來源與數字，可以直接使用。§12 與簡報第 24–25 張（AI 撰寫規範文件）是本次新寫的教學設計，沿用 `Unit_01/persona-prompt.html`、`Unit_02/interview-prompt.html` 已建立的提示詞頁寫法，尚未實際在課堂測試過，建議你使用前先讀一遍、視班級狀況調整用詞與範例。

## 課程內容

- §1–§11（案例）：iOS / Android 規範概念、單位、Safe Area、導覽、觸控、表單、無障礙、作業與雙平台對照總表。
- §12（新增）：規範文件的三步驟寫法——草稿、找漏洞、轉檢核表，附三份可複製的 AI 提示詞。
- AI 不能取代的部分：數字核對、規則取捨、實際套用驗證。
